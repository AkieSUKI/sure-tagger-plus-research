本文把“用一组小模型和工具为语音任务提供可复用证据”写成一个统一的设计问题。它解释
下式中的每一项是什么意思，并给出从 `tag-schema` 继续往前建设所需的标签选择、模型能力
边界、互相印证和开源模型调研方法。

本文讨论的是任务的证据接口，不把任何单个模型的输出当成物理真值。模型输出先成为带有
来源、时间范围和不确定性的观察，经过规范化、冲突处理和确定性派生后，才可以成为下游
LLM 或业务程序可消费的证据。

## 1. 核心思想

图中的中心表达是：

$$
T = \operatorname{LLM}(\operatorname{Evidence}(t_1,\ldots,t_n)).
$$

它把语音理解拆成两个问题：**感知层提供可组合的证据，LLM 理解这些证据并组织必要的复核。**
要让这件事可实现，先区分 tag 的定义和一次音频上的取值：

| 符号 | 含义 | 示例 |
| --- | --- | --- |
| `x` | 原始音频 | 一段多人会议录音 |
| `T` / `q_T` | 任务及其要求 | 判断某人是否打断另一人，并定位时间 |
| `t_i` | tag 类型，即感知语义坐标 | speaker activity、文本、词时间、语言 |
| `v_i(x)` | 某次观察对该 tag 给出的值 | 一组带 speaker ID 的活动区间 |
| `e_i(x)` | 带值、作用范围、来源和不确定性的 evidence | 区间、模型版本、音频窗口、置信信息 |
| `S` | 被选择的 tag 类型集合 | 文本 + speaker 活动 + 时间关系 |
| `m_j` | 产生观察的模型或工具 | ASR、VAD、diarizer、规则函数 |

一项 evidence 可以表示为 `e_i = (tag_id, value, scope, provenance, uncertainty)`。
同一 tag 可以有多个候选观察；这些候选不应在规范化时被静默合并。严格一些，图中的公式应写为：

$$
E_S(x)=\operatorname{Normalize}\bigl(\{e_{i,r}(x):t_i\in S\}\bigr),
\qquad
\hat y_T=\operatorname{LLM}(q_T,E_S(x)).
$$

其中 `r` 区分同一 tag 的 producer、配置或重复观察，`ŷ_T` 是任务的预测结果。
`Evidence` 包括 tag 的值，也包括时间关系、speaker 关系、依赖图、缺失和冲突。
仅有“人数=2、重叠=true、整段转写”仍不足以回答“谁在什么时候打断了谁”。

“任意任务都可以这样表示”是架构目标，需要对指定任务族验证：是否存在一个有限的 `S`，
能在允许的误差内保留完成任务所需的信息。有限 tags 可能丢失重音、罕见声音或细节；LLM
不能可靠恢复这些已经丢失的事实。证据不足时，应回到原音频增加观察或扩充 schema。对语音
生成、波形增强等任务，还需要相应的解码或信号处理模块，不能仅凭文本 LLM 输出替代波形。

## 2. 在覆盖与规模之间选择 tag 集合

感知维度可以不断细分，图中用 `n → ∞` 表示这种开放性。问题是：在任务需求持续扩展时，
怎样用可维护的一组坐标覆盖尽可能多的证据？单纯增加 tags 会增加成本、重复信息和错误传播。

需要同时区分两种选择：

- **共享 schema 基底 `S*`**：面向任务族 `𝒬`，例如转写、逐人归属、对话分析、音频检索和质量筛选。
- **任务运行子集 `S_T ⊆ S*`**：对当前任务按需取证；简单字幕不必调用所有场景或情绪模型。

设 `𝒯` 为候选 tag 类型集合，`C_𝒬(S)` 为在任务分布和真实音频上测得的覆盖/效用，
`R_T(S)` 为任务 `T` 的误差或风险。一种直接对应“k 尽量小、空间尽量大”的形式为：

$$
\min_{S\subseteq\mathcal T}|S|
\quad\text{s.t.}\quad C_{\mathcal Q}(S)\ge C_0,\quad
R_T(S)\le\epsilon_T\;\;\forall T\in\mathcal Q_{\mathrm{critical}}.
$$

`C₀` 是任务族的最低覆盖目标，`ε_T` 是关键任务允许的误差预算。平均分不能掩盖某一种
语言、overlap 场景或关键任务完全失效。实际还可以用下面的目标比较 Pareto 候选：

$$
\max_{S\subseteq\mathcal T}\left[
C_{\mathcal Q}(S)-\alpha|S|-\lambda\operatorname{Cost}(S)
-\mu\operatorname{Risk}(S)-\rho\operatorname{Redundancy}(S)\right].
$$

`α、λ、μ、ρ` 是预先声明、用于统一各项尺度的非负权重；不声称它们是通用常数。
Cost 同时记录调用成本和 schema 维护成本；Risk 记录未验证边界和错误传播；Redundancy
只惩罚缺少增益的重复，不能把有价值的独立复核一并删掉。多个 tags 来自同一次模型调用时，
模型成本按调用集合计一次，不能逐 tag 重复累加。

这里 `k = |S|`。压缩 `k` 时应固定 tag 的语义粒度，并同时报告字段复杂度和表示大小。把所有信息塞进一个
`all_audio_features` 对象，形式上 `k=1`，并不代表找到了更好的最小基底。

不同 tags 还存在协同：文本和时间轴单独都不能完成逐人归属，合用才有价值。若 `C(S)`
表示在固定任务集上的效用，二阶协同量可以写成：

$$
\operatorname{Synergy}(a,b\mid S)=
C(S\cup\{a,b\})-C(S\cup\{a\})-C(S\cup\{b\})+C(S).
$$

它是一个用于消融的交互量，不自动证明统计独立或因果作用。只有验证了边际递减等条件，
才能引用相应的贪心近似保证；一般情况下应比较单 tag、组合删除和替代模型组合的收益。
这里的“基底”是任务分布、质量门槛和预算下的工程选择，可能存在多个同样合理的解。

### 2.1 “空间尽量大”的可操作定义

“空间大”必须相对于任务和下游动作定义，不能用 tag 数量代替。建议把任务需求拆成三类：

- **事实维度**：是否有人声、人数、语言、文本、背景事件、音质等。
- **关系维度**：谁在什么时候说话、哪些词属于哪个 speaker、两个事件是否重叠、哪个模型
  支持某个结论。
- **不确定性维度**：缺失、冲突、置信度、时间范围、版本和失败原因。

令 `D_T` 为任务需求集合。对每个维度定义覆盖函数 `c_d(S) ∈ [0,1]`，再按非负且总和为 1
的任务权重 `w_d` 计算：

$$
\operatorname{Coverage}_T(S)=\sum_{d\in D_T}w_d c_d(S).
$$

例如，单人字幕任务不需要完整的 diarization，但需要高质量 ASR、语言、词级时间和失败
标记；多人逐人转写则必须同时覆盖 lexical units、活动时间轴和 speaker 映射，不能用整段
ASR 的语义连贯性替代归属证据。

先统计需求是否可表达，再用真实任务指标衡量是否可靠；二者分别报告。多人转写可使用
WER/CER、cpWER、DER、人数误差、时间边界误差和拒答率，任务答案另做端到端评测。
`c_d` 可以依赖一组 tag 的联合可用性，不能把“字段非空”直接当成正确覆盖。

## 3. tag、evidence 和派生结果的分层

建议把一个公开字段拆成四层，避免模型输出、规则结果和自然语言混在一起：

```text
原始观察 observation
    -> 规范化 evidence
        -> 确定性 structural tag / derived tag
            -> LLM descriptive output
```

### 3.1 原始观察

原始观察保留模型实际输出及运行上下文，例如 ASR 的 segment、diarization 的活动区间、
VAD 的 speech interval、DNSMOS 的分数。原始观察不直接覆盖旧结果，采用追加写入并保留
`evidence_id`。

### 3.2 规范化 evidence

规范化层统一：

- 原音频坐标、窗口坐标和时间变换；
- 单位、采样率、枚举值和数值精度；
- 样本内 `speaker_1..speaker_N` 的确定性编号；
- `null`、空数组、零值、低置信度和工具失败的区别；
- `source_evidence_ids`、模型版本、checkpoint、配置和许可证。

一条 evidence 至少应记录：

```text
evidence_id / sample_id / kind / status
tool / model / model_version / checkpoint_sha256 / runtime
audio_sha256 / view_id / transform_id / start_sec / end_sec / time_mapping
raw_payload / normalized_payload / parent_evidence_ids / quality / failure_reason
```

### 3.3 结构性 tag 与确定性派生

结构性 tag 是通过发布合同的上游观察，或由固定公式、集合关系、字符串规则和时间运算唯一得到的
结果。只要一个事实需要被筛选、计数或评测，就应该落成结构化字段，不能只藏在 caption
或描述性短语中。例如：

$$
\texttt{speaker\_present} = (\texttt{speaker\_count}>0),
$$

$$
\texttt{speaker\_change\_rate\_per\_min}
 = \frac{60\times\texttt{speaker\_change\_count}}
        {\texttt{duration\_sec}}.
$$

这与现有 `tag-schema.md` 的结构性/描述性划分一致。结构性表示字段的计算/发布合同，
不保证其预测正确。当前 schema 后接描述 LLM 的只读约束要保留；需要改变一个结构性结论时，
应走显式的候选选择、复核和重新发布流程。`false`、`0` 和 `[]` 是有意义的观测结果，
不足或失败写 `null`，并在 evidence 中保存具体原因。

### 3.4 描述性输出

LLM 可以根据结构化 evidence 生成 caption、topic、场景假设和 usability note，但必须：

- 引用真实存在、非 `null` 的 `evidence_tags`；
- 把事实、推断和假设分开表达；
- 不从 pitch、语言或描述文本推断年龄、身份、情绪、地点等未覆盖维度；
- 结构性 evidence 缺失时保留不确定性，不用流畅文字填空。

### 3.5 LLM 如何“理解或修正”证据

用户提出的修正能力是闭环的一部分，可以分为四种动作：

| 动作 | 示例 | 形成的结果 |
| --- | --- | --- |
| 解释 | 根据有来源的文本概括主题 | 引用 evidence 的描述或任务答案 |
| 选择/重解释 | LID 与原文冲突时选择更有支持的语言候选 | 新的 resolution 记录，保留原 LID 和选择理由 |
| 派生/提出候选 | 从 ASR 原文识别文本语言，提出疑似错词候选 | 依赖原文 hash 的派生观察或待验证假设 |
| 补充感知 | 裁剪冲突时间窗、换 producer 或配置重听 | 新的音频观察，经合同检查后更新当前结论 |

原始观察保持不可变，当前被接受的解释可以更新。若任务允许文本纠错，也应保存原文、候选、
修改理由和验证状态；未获音频支持的改写不能冒充声学观察。当前多说话人公开 ASR 的合同更严，
只允许选择已有文字，不允许 Planner 生成替代转写。这是该实现的约束，不是所有未来任务的通则。

```mermaid
flowchart LR
    X["原始音频"] --> M["小模型与工具"]
    M --> E["不可变观察 + 时间与来源"]
    E --> R["规范化与候选证据"]
    R --> L["LLM 理解、发现缺失与冲突"]
    L --> P["选择证据 / 请求定向复核"]
    P --> M
    P --> V["验证、派生与版本化采纳"]
    V --> Y["结构化结果 + 任务答案"]
```

## 4. 用“向量空间”理解模型和 tag 的关系

图中的 `t1 + t2`、`x*tp + y*tq` 不要求 tags 真正是可相加的标量。它表达的是一种
坐标变换：不同的 tag 组合可以描述同一任务相关状态。

令任务相关状态为 `z_T`，每个工具输出 `z_j`。一般关系写为带误差的观察映射 `z_j = h_j(z_T, ε_j)`；在选定数值编码且线性近似成立时，才可以用下式作类比：

$$
m_j:x\mapsto z_j,
\qquad
z_j = A_j z_T + \epsilon_j.
$$

这里 `A_j` 表示该模型能看到的子空间，`ε_j` 表示噪声、偏差和未观测部分。
例如，VAD 主要覆盖“何时有人声”，diarization 覆盖“哪些活动属于同一说话人”，ASR
覆盖“说了什么”，forced aligner 覆盖“已有文本在何时发生”。它们的输出不是同一个向量，
但可以共同约束一个 speaker timeline 和逐人转写状态。

一个模型集合 `M_a = {m₁, m₂, …}` 与另一个集合 `M_b` 如果在任务所关心的
维度上提供足够接近的证据，就可以比较它们是否能替代彼此：

$$
\phi_{M_a}(x)\approx_T\phi_{M_b}(x)
\iff
\operatorname{Answer}_T(\phi_{M_a}(x))
\approx
\operatorname{Answer}_T(\phi_{M_b}(x)).
$$

`φ_M` 表示模型集合 `M` 经适配器形成的 evidence，`Answer_T` 表示同一个下游任务处理器。
式中的 `≈` 必须按任务指标解释，例如在 WER、DER、cpWER、时间边界容差或校准误差不超过
预设容差 `δ_T` 时才认为可替代。容差近似不一定满足传递性，因此这里不声称构成严格的
线性基变换或商空间；单个样本答案相同也不足以证明两个模型集合覆盖相同。

这不是说两组模型的原始输出相同，而是说它们对当前任务提供了可替换的支持。模型集合
可以有不同粒度，例如：

```text
m1 = ASR + language evidence
m2 = diarization + overlap timeline
m3 = VAD + deterministic profile

或

m1' = joint ASR-diarization
m2' = lexical ASR + forced alignment + independent diarization
```

因此图中的 `m1 = t1 + t2` 应读作“模型或工具 `m1` 的一次调用联合产生 `t1`、`t2` 两类
观察”，`m2 = t3 + t1` 则表示另一种调用同时覆盖 `t3` 和 `t1`。这里的加号表示输出集合
或覆盖关系，不是把异构的文本、区间和分数直接做数值相加；相同的 `t1` 也不能因为由
两个模型产生就自动变成真值，仍需统一语义、坐标、版本和冲突规则。

两种分解都可能支撑“逐人转写”，但它们的失败模式不同。只有当来源、视图、训练数据或
错误模式足够独立时，交叉结果才有互证价值；同一模型同一 checkpoint 的两次调用不能被
当成独立证据。

## 5. 用模型和小工具表示 tag

每个 producer 都应声明能力边界，而不是只写一个模型名称。推荐用以下六元组登记：

```text
capability        能产生的原子能力
input_view        需要的输入（整段、窗口、clean crop、已有文本等）
output_contract   字段、类型、单位、时间坐标和空值语义
evidence_quality  评测指标、校准方式、适用语言/场景
unsupported       明确不能推出的结论
provenance        版本、checkpoint、代码、许可证、硬件和日期
```

### 5.1 能力原子索引

这张表按语义需求发现能力，不把同一行的所有输出都归给每一个模型。真正登记时，使用
“具体 producer + 版本 + 能力”一行的记录（见下一节），分别核对输入、输出、许可证与成本。

| 能力原子 | 调研起点 | 证据与关键边界 | 首要验证 |
| --- | --- | --- | --- |
| 语言识别 | FireRed LID、Qwen3-ASR；ASR 后的文本语言识别 | 音频 LID 与文本派生语言是两条不同边；文本结果依赖 ASR 正确性 | 短文本、混语、同文字系统、指定语言造成的偏置 |
| 转写 | FireRedASR2-AED、Qwen3-ASR、MOSS | 粒度按 producer 核对；整段文本不等于逐人或词级文本 | WER/CER、噪声、口音、长音频、overlap |
| 文本时间定位 | Qwen3-ForcedAligner、WhisperX、CTC segmentation | 需已有文本；对齐不等于识别正确，也不产生 speaker 身份 | 时间边界、错误文本、窗口偏移、支持语言 |
| 说话人活动与聚类 | MOSS、Nemotron、DiariZen；EEND/TS-VAD 作为补充调研 | 活动区间、样本内 ID、重叠；ID 不代表实名身份 | DER、短 turn、跨窗口映射、人数误差 |
| 语音活动 | FireRedVAD 等 | speech/non-speech 区间；non-speech 不等于物理静音 | miss/false alarm、音乐、低信噪比 |
| 说话人性别候选 | 现有 Alice、AfriSpeech、Griko 路由 | 当前项目合同中的分类候选；pitch 不能替代分类证据 | 语言覆盖、clean 音频、样本时长、校准 |
| profile | F0/RMS/coverage 和文本统计工具 | 相对音高、片内音量、语速；不自动推出年龄或情绪 | 依赖与单位、重叠剔除、阈值 |
| 质量/房间 | DNSMOS、Brouhaha、Rec-RIR | 分别核对质量分、SNR、估计 RIR 的派生指标；不直接等于场景类别 | 真实标注、通道/分窗配置、域偏移 |
| 声音事件 | FireRed AED、DASS | AED 可提供事件区间；当前 DASS 为分窗分数和聚合类别，不能虚构精确时间轴 | 类别映射、门槛、长尾事件 |
| 声纹 | CAM++、ECAPA | 相似度或 embedding；不直接给出实名身份 | 域偏移、阈值、同源误差 |
| 综合音频理解 | Qwen3-Omni 等 | 观察/描述候选；能力和成本需与专用模型按同一任务比较 | 提示敏感性、错误率、结构一致性 |

#### ASR 不只等于“转写”

一项 ASR 调用可能显式提供语言码，也可能只给文本。至少区分三条路径：

1. `audio → ASR 的原生 LID 输出`：由模型直接报告，但需检查是否只是回显输入的强制语言。
2. `audio → ASR text → 文本语言识别器/LLM`：可以补充或修正语言候选，是可复用的派生能力。
3. `audio → 独立音频 LID`：增加不同观察路径，可用于核对前两者。

第二条依赖 ASR 原文，必须记录 `parent_evidence_ids` 和原文 hash。同一个错误转写经两个
文本分类器都判为英文，不是两份独立的“音频为英文”证明。短句、专名、空文本、翻译输出、
混语和多个语言共享字符集时，要保留不确定性。时间戳也需区分 ASR 原生输出与 wrapper
额外调用 aligner 的结果；streaming 接口存在不代表该模式支持时间戳。

见第 11 节；未取到的 checkpoint/license/runtime 指标明确留作 `unknown`。

延迟、失败情况和本地测试状态。“文档记载可用”和“本次健康检查成功”必须分列。

### 5.3 状态和空值合同

能力来源类型与实施状态分列。`source_kind` 记录 `official_doc/code/paper/local_doc/local_probe`；
以下实施状态不能用来源等级替代：`implemented`（已核查当前代码会发布）、`observed`（本地运行看到过）、`proposed`（设计候选）、`unknown`（没有足够资料）、`unsupported`
（已知不应推出）。一次 evidence 的运行状态再单独使用：

```text
available       有合法值且通过类型/范围校验
negative        明确观察到否定结果，例如 false、0 或空事件集合
unavailable     producer 没有返回可用观察
error           producer 运行失败，保存异常和版本
low_confidence  有值但低于该 tag 的发布阈值
conflict        两个或多个独立来源在同一语义坐标上冲突
abstain         规则或 Planner 主动拒绝发布
```

公开 schema 可以把 `unavailable/error/low_confidence/conflict/abstain` 映射为 `null`，但
evidence store 和 trace 必须保留原状态、`failure_reason`、来源和阈值。`false`、`0`、`[]`
只能在 producer 真的观察到否定结果时使用，不能把失败写成空结果。

## 6. 当前 `tag-schema` 的位置与缺口

外部参考文件为 [tag-schema.md](../research/speech-evidence-space-20261020/visualization/baseline-tag-schema.md)。
它已经提供了一个可用的公开字段合同：六个原始顶层分组、`deterministic_derived`、
`descriptive`，并用 Layer 1–5 索引 lexical、speaker、temporal、paralinguistic 和
acoustic scene 维度。多说话人设计文档进一步给出了“观察→证据→决策→Planner→组装”的
闭环，以及 route/version、baseline evidence 和停止条件。

当前 schema 的强项是：

- 区分结构性字段与开放式描述，避免让 LLM 改写固定结果；
- 对 `null`、空数组、零值和 `evidence_tags` 有明确语义；
- 用模型/阶段/公开字段映射表追踪生成链路；
- 允许叶字段独立评测，不把一个上游失败传播成所有字段失败。

当前缺口不是再增加若干描述性字段，而是补一个“能力原子→tag→producer→评测”的总表。
按五层标准，优先缺少：

1. 完整 rich transcription：词级时间、标点位置、ITN/normalization、口吃/自我修正、
   filler 保留策略和片段级 code-switching。
2. 时间结构：带起止时间的 turn、gap、turn duration、backchannel 和稳定的 overlap 事件。
3. 说话人与属性：跨窗口身份链接、可审计的 speaker attribution、年龄/角色等需要单独定义与验证的属性；不能从现有 profile 猜测。
4. 副语言与非言语：emotion/affect、重音/韵律事件、笑声、叹息、咳嗽、音乐和其它 vocal
   event 的时间轴。
5. 声学场景：IHM/MDM/SDM、近讲/远场、电话/会议/广播等 channel/domain 标签，以及
   离散化的 SNR、混响等级。

这些缺口要先变成能力原子和评测任务，再决定是否进入公开 schema。没有稳定 producer、
输出合同和独立 GT 的维度，可以暂存在内部 evidence 中，不能直接升级为结构性公开字段。

对内部 evidence 与公开 schema 分别审计：例如项目已有部分时间轴/词时间 sidecar，并不表示
公共 JSON 已有同名字段，也不表示这些维度完全没有 producer。建议先形成以下 gap register：

| 缺口 | 为什么需要 | 候选方向 | 验证与进入基底条件 |
| --- | --- | --- | --- |
| 词/段时间与关系表达 | 支撑逐人归属、事件先后和引用定位 | 对齐器 + 统一原坐标 sidecar | 人工边界、单位覆盖；定位类任务的核心维度 |
| overlap 中逐人内容 | 相同混音窗口不能自动分离两人 | 联合 ASR、目标说话人 ASR/分离 | overlap 分层 cpWER、归属错误；高收益但待验证 |
| 片段级语言 | 全段语言码不能表达 code-switch | 分段 LID/ASR + 文本语言候选 | 片段语言 GT；多语任务按需启用 |
| 非言语发声与韵律 | 词文本会丢失笑声、强调和表达方式 | vocal event、F0/能量、prosody 工具 | 事件时间 GT、语义增益消融；当前候选扩展 |
| 情绪/通道/领域 | 现有 profile 或质量分不足以独立证明 | 专用分类器、元数据及其它可验证来源 | 明确定义、标注一致性、域外验证；未验证不进入稳定字段 |

每项继续补 `status/source/owner/next_action`。优先补能让一类任务从“无法表达”变为
“可以验证”的证据，而不是为了凑齐分类表添加低价值字段。

## 7. 开源模型调研的统一方法

调研目标不是罗列模型名称，而是回答：“这个模型是否能以可追溯、可复现的方式填充某个
能力原子？”每个候选模型至少记录：

```text
capability_id / model_name / repository / paper_or_model_card
license / release_date / commit_or_checkpoint / runtime
supported_languages / input_limits / output_contract
training_data_notes / benchmark_and_metric / hardware_cost
known_failures / unsupported_claims / integration_status
source_urls_or_paths / checked_at
```

资料类型与验证程度应分开记录：

- **官方声明**：官方仓库、model card、论文和许可证声明了接口或能力；注明对应版本。
- **实现核查**：在具体源码/适配器中确认可调用路径、字段和后处理；不等于证明准确率。
- **本地验证**：在声明的 probe/评测集上实际运行，保留版本、输入、输出和指标。
- **待核验线索**：二手资料、项目建议或未复现 demo，只用于候选发现。

任何一级都不能单独证明在所有任务上的正确性。调研必须区分“模型宣称能做”“默认配置
会做”“当前适配器实际发布”“目标数据上做得好”这四件事。

### 7.1 调研起点与扩大搜索范围

本轮读取了本地 schema、设计和研究资料，未进行新一轮全网模型普查。下面是交给后续
agent 的起点，不是“最新模型已调研完毕”的结论。资料复核日为 2026-10-20，缓存日期和
其中模型 release/revision 分开记录。

| 起点 | 可追溯资料 | 已知内容 | 未完成事项 |
| --- | --- | --- | --- |
| Qwen3-ASR / ForcedAligner | R3 的官方 README 快照；[官方仓库](https://github.com/QwenLM/Qwen3-ASR)作为更新核查入口 | LID+ASR、离线/流式、长音频声明；独立 aligner 的语言和时长限制 | 最新 commit、代码与权重许可证、本地目标域质量/延迟 |
| MOSS | R4 本地源码核查 memo、R2 项目链路 | 段级联合输出与接口限制 | 回读对应官方代码/model card，固定 checkpoint，验证 overlap 和 ID 映射 |
| Nemotron / DiariZen | R2 和 R1 的不同路由记录 | 各自的时间轴用途及版本差异 | 按运行配置和适配器核对，不根据模型名替换 producer |
| Whisper / WhisperX / CTC alignment | R5 词时间调研 | 可作为 ASR/对齐的替代路径线索 | 更新官方源、核对是否额外下载模型、语言/时间粒度与费用 |
| EEND / TS-VAD / 目标说话人 ASR | R6 及 R4 的 overlap 分析 | 活动估计、参考声纹与分离/转写的职责不同 | 核查代码/权重可得性，寻找真实可运行的替代组合 |

搜索应按能力缺口展开，包含现有栈之外的候选：目标说话人分离/ASR、情绪和韵律、非言语
发声、声学事件、片段语言识别、音频 embedding/检索、声学质量和通道条件。每类记录搜索词、
日期、官方入口、候选纳入/排除理由；有条件时比较不同模型家族，避免把同一个 checkpoint
的多个 wrapper 当作多个独立方案。

在 registry 中把 `code_available`、`weights_available`、`commercial_use_allowed`、
`runs_here`、`healthchecked` 分开记录，未核实用 `unknown`，不要用 `false` 代替未知。
代码开源不等于权重已发布，也不等于该版本可以在本机复现。

### 7.2 待执行的最小 probe 方案

本节是验证计划，本轮未执行。每次 probe 保存音频 hash、真值、producer revision、输出、
可用的置信信息、延迟和分歧判定。最终结论使用独立 held-out 数据，不能把已用于调参的
probe 当成独立测试；同一录音的裁剪不要跨训练/调参/测试拆分。

| probe 场景 | 预期核验 | 主要指标/判定 |
| --- | --- | --- |
| clean single speaker | 转写、人数、语言基线 | WER/CER、语言正确率、人数、延迟 |
| silence / non-speech | 真正的无语音与运行失败能区分 | false alarm、negative/null 状态、空音频幻觉 |
| music / singing / BGM | 事件与转写能力分别检查 | event precision/recall、WER、路由错误 |
| noise / reverberation | 质量预测与文本退化能分别追踪 | 有 GT 的质量误差、WER 增量、失效条件 |
| overlapping speakers | 活动重叠和逐人文字是否各自有证据 | DER、overlap F1、cpWER、拒答率 |
| short turns / boundary jitter | 短段、偏移与跨窗 ID 正确 | 边界误差、映射错误率 |
| multilingual / code-switch / accents | 全段语言与局部语言区别明确 | language/segment F1、各语言 WER、abstention |
| 同一音频的正确/错误/无关语言提示 | ASR 语言输出是否被输入条件强制回显 | 与 audio-only 对照、错误提示误改率 |

互证评估还要看两个 producer 的条件错误相关性、共同失败比例和新增正确覆盖率；一致率高
可能只是共同出错。语义覆盖、模型可靠性、调用成本和独立复核价值应分别报告。

## 8. 从任务到最小 tag 基底的工作流

### 8.1 任务→evidence 合同示例

以“多人逐人转写”为例，先把输出需求写成可评测的 evidence 合同。下面的 `status` 是
当前项目资料下的初始判断，不代表所有 producer 已完成健康检查。

| 任务需求 | 最小 tag/evidence | 类型与分辨率 | 主要指标 | status / 依赖 |
| --- | --- | --- | --- | --- |
| 样本级语言路由 | `language_content.language` + `language_route` | enum；样本级 | language accuracy、混语 abstention rate | `implemented`；FireRed LID，路由版本 |
| 整段内容 | `speaker.asr_transcript` | text；整段或段级 | WER/CER、文本可用率 | `implemented/observed`；语言 route + ASR |
| 人数与活动 | `speaker.speaker_count`、activity evidence | integer + intervals；样本/段级 | count MAE/F1、DER | `implemented`；选定 decision timeline |
| 重叠 | `speaker.speaker_overlap`、`overlap_ratio` | bool + ratio；样本级 | overlap F1、ratio MAE | `implemented/derived`；activity union，分母非零 |
| 逐人词/段文本 | `t_lexical` + `t_attribution` | text units + speaker-local intervals | cpWER、speaker-attribution accuracy | `proposed`；ASR/aligner + timeline 交集 |
| 不确定性与审计 | `evidence_id`、source、status、failure_reason | record；每次观察 | provenance completeness、replay success | `proposed`；所有 producer 必须写入 |

公开 schema 当前只有部分 `speaker.*` 路径；`t_lexical`、`t_attribution`、activity intervals
可以先作为内部 evidence，经过独立评测后再决定是否公开。每一个 tag 的记录至少补齐：

```yaml
id: t_attribution
definition: lexical unit 与样本内 speaker 的可审计时间交集归属
class: observed | derived
type: interval_assignment
scope: word | segment | speaker
resolution: source-unit time; original audio coordinates
unknown_semantics: 无法唯一归属、时间轴冲突或 producer 失败
producer_edges: [qwen3_asr, qwen3_forced_aligner, diarizer]
dependencies: [t_lexical, t_activity]
validation: cpWER + attribution accuracy + overlap probe
status: proposed
```

### 8.2 任务建模

对每个任务写出：输入视图、输出字段、允许的未知值、评测指标、预算和不可接受的错误。
把输出拆成事实、关系和不确定性三类需求，得到 `D_T`。

### 8.3 候选 tag 生成

从现有 schema、任务缺口、模型能力矩阵和确定性规则中生成候选。每个候选必须绑定：

```text
tag_id / semantic_definition / type / support
producer_candidates / dependencies / null_semantics
quality_metric / cost / risk / version
```

### 8.4 选择与消融

先按 coverage/cost/risk 选出候选基底，再做消融：移除一个 tag，检查任务质量下降、冲突
可解释性和失败可恢复性。优先保留能覆盖不同错误模式的互补 tag，而不是保留多个同源
高相关输出。

### 8.5 互证与冲突

对同一事实使用不同 producer 时，先定义冲突对象和合并规则：

- 文本冲突：保存每个候选及文本 hash，不能由 Planner 凭流畅度改写；
- 时间轴冲突：统一原坐标后计算重合、覆盖和 ID 映射；
- 语言冲突：保留原始 LID，新增派生语言 evidence；只有在 `run_config` 声明了 route policy、
  候选具有相同样本范围且存在唯一可审计选择时才切换路由，否则保留原路由并 abstain；
- 质量冲突：保留分数与失败原因，不把“某模型失败”改写成“没有事件”。

通用 resolver 规则是：先按同一语义、坐标、单位和版本合同对齐；再应用配置中的 producer
优先级、质量阈值和适用范围；仍无法唯一选择时输出 `conflict/abstain`。禁止把两个不兼容
的置信分数平均，也禁止用另一模型的失败填补当前模型的空结果。每次选择写入
`resolution_id`、候选 evidence、规则版本和理由。

在当前多说话人链路中，Planner 只选择已有 evidence、窗口或冻结配置；它可以请求 `ProbeWindow`、`ProbeConfig`、
`Accept`、`Wait/Abstain`，但不直接生成 ASR、修改文字或写入结构性 tag。

### 8.6 冻结和发布

确定性 resolver 生成结构性字段并记录规则版本；LLM 只读生成描述性字段；schema、来源
引用和校验通过后再发布 JSONL。每次运行至少保存：

```text
tags.jsonl / evidence/ / planner_trace.jsonl
run_config.json / route_version / model_registry_snapshot / eval/
```

## 9. 一个多人逐人转写任务的示例

任务要求是：输出总 ASR、人数、重叠、每个 speaker 的文本和可审计的不确定性。

一个候选证据包如下；其中原始感知、派生关系和元信息分开计数，不声称已经求得最小 `k`：

```text
t_language       样本级语言与路由 evidence
t_lexical        带来源的 ASR 文本或 lexical units
t_activity       统一坐标的 speaker activity timeline
t_overlap        由 timeline 确定性计算的 overlap
t_attribution    lexical unit 与 speaker 的时间交集归属
t_provenance     模型、窗口、版本、失败和冲突记录
```

`t_overlap` 可由 `t_activity` 派生，`t_attribution` 依赖 lexical 与 activity，
`t_provenance` 是通用元信息。它们不应全部作为新增独立感知维度计入 `k`；这些 `t_*` 是
本文的概念 ID，公开字段仍遵循现有 schema。删除时间轴会失去逐人归属；从基底中删除可重算
的 overlap 布尔别名则未必损失信息。这就是区分必要坐标和便利派生字段的一次消融论证。

一种表示是 `MOSS joint ASR-diarization`；另一种表示是
`Qwen3-ASR + ForcedAligner + 独立 diarization`。两者都可能生成 `t_lexical + t_activity`
的任务相关表示，但第二种明确知道 aligner 只对齐已有文本，第一种则需要检查联合模型的
speaker 身份和重叠行为。独立时间轴可以发现联合模型的漏检，联合 ASR 可以在归属验证通过
时保留带 speaker 的句段；任何一方失败都不应被静默地补成另一方的结果。

以下字段是从 evidence 确定性生成的，而不是让 LLM 估计：

```text
speaker_present       = speaker_count > 0
multi_speaker         = speaker_count >= 2
speaker_overlap       = overlap_duration > 0
overlap_ratio         = overlap_duration / speech_union_duration
speaker_change_rate   = speaker_change_count * 60 / duration_sec
```

这些公式只在依赖合法时发布：`speaker_count` 缺失则人数相关布尔字段为 `null`；
`speech_union_duration <= 0` 或 overlap/时间轴缺失则 `overlap_ratio=null`；
`duration_sec <= 0` 或切换次数非法则 `speaker_change_rate=null`。公开比例和速率按 schema
合同四舍五入到 6 位小数，内部同时保留原始时长、分子和分母。

LLM 可以解释“有两名说话人且存在短时重叠”，但这个句子必须引用上面的结构性字段；若
归属不可靠，内部 evidence 标为 `ambiguous` 并保留来源，公开逐人字段按合同使用 `null`；
不能凭语义把整段文本拆给不同的人。

## 10. 验收标准与后续建设

新 tag 或新 producer 进入稳定链路前，至少应通过以下检查：

1. **语义检查**：定义能被另一个人独立理解，正例、负例和未知例明确。
2. **边界检查**：写出输入、输出、支持范围、不能推出的结论和失败语义。
3. **来源检查**：可定位到模型版本、代码/仓库、配置、许可证和运行日期。
4. **一致性检查**：同一任务的多种表示有明确的对齐、冲突和停止规则。
5. **质量检查**：有针对能力原子的 GT、指标、校准或人工复核方案。
6. **消融检查**：能说明该 tag 对 coverage、成本、风险或可恢复性的实际贡献。
7. **回放检查**：旧 evidence 可以重放，新增 producer 不会覆盖不可变 baseline。

推荐的建设顺序是：

```text
能力原子与 registry
  -> tag contract 与 provenance schema
  -> producer 适配器和独立评测
  -> 最小基底选择与消融
  -> resolver / Planner / 描述性组装
  -> route、模型和 schema 的版本化发布
```

最终目标不是让一个大模型“知道所有音频事实”，而是让系统用少量、可解释、可组合的
观察坐标覆盖任务真正需要的证据空间，并在证据不足时明确地保留未知。
