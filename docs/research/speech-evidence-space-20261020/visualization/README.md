# 声音证据图谱

直接用浏览器打开 [index.html](index.html)。页面使用本地 HTML、CSS、JavaScript 和数据快照，不需要安装依赖、连接外部服务或运行模型。保留同目录文件；发布版使用系统字体，不依赖本机字体文件。

也可以在项目根目录运行静态服务：

```bash
cd sure-tagger-plus-research
python3 -m http.server 8765 --bind 127.0.0.1
```

访问 `http://127.0.0.1:8765/docs/research/speech-evidence-space-20261020/visualization/`。若在远程机器上运行，可在 IDE 中转发 8765 端口。服务从仓库根目录启动，页面中的原始文档链接也可访问。

## 使用

- 默认打开 [SURE-Tagger 能力表](index.html#sure)：按现有 34 个结构父字段展示模型/完整路径，可多选、搜索、清空并查看字段详情。有依据、条件候选与未确认分别显示，`far_field` 无支持连线，sidecar 不计公共覆盖。
- 新版下方有“同一 tag · 多路径”和“不同 tag · 互相约束”：各 8 组检查。选中模型时，相关卡片提示“与所选组合有关”；这不表示已经运行检查。字段详情同时列出两类相关关系，派生自检和诊断线索有单独说明。
- “研究关系图”保留“Qwen3-ASR + 对齐器 + 说话人分离角色”的逐人转写预设。使用组合预设，或点击左侧模型节点多选；已选模型及其满足条件的标签、曲线会高亮，其他节点淡化。
- 实线表示有依据的路径，虚线表示含 `[H]` 的待验证路径；两者分别计数。∅ 标签始终显示为尚无确认模型，旧 OASR 不可调用节点不能选择。
- 搜索模型、标签 ID 或中文含义；按 L1–L6 筛选，或打开“只看当前组合”。长图在面板内滚动，小屏可以在面板内横向滚动。
- 点击标签查看定义、范围限定、各条模型路径、缺失组件和旧版对应；“补齐此组合”保留已选模型并补上缺少的组件。
- “标签变化”按新增、细化、派生、元数据、描述输出与暂缓分组，支持搜索新旧字段。点击 `t_*` 可跳回关系图。完整依据见 [标签版本对比](../标签版本对比.md)。
- “跨标签检查”展示 8 类跨维度关系：语言与转写、文字与时间、说话人归属、事件与活动、事件与声源、情绪与声学特征、质量与转写、局部语言切换。关系卡中的双向连接表示互检，支路说明展示不同输出的来源；支持分类、搜索和点击标签跳回原图。它们是待评测的检查方案，不计入 producer 覆盖，也不表示已通过独立真值评测。完整定义见 [Schema §8.1](../tag_schema.md#81-跨标签一致性检查互检链路)。
- “导出当前组合”下载 JSON，含模型、覆盖标签、候选标签、满足的原始路径和源文件指纹。

## 组合与计数规则

新版数据来自 [SURE-Tagger 模型能力对应表](../SURE-Tagger模型能力对应表.md) 和 [JSON](../SURE-Tagger模型能力对应表.json)。34 个结构父字段包括当前 main 的 33 个字段及 compare 已有的 `speaker.speaker_transcripts`；复合字段的子字段不重复计数。图中模型组合节点是完整产出路径或路由家族；选择它不表示已经并行运行所有替代模型。

原研究关系图来自 [模型与标签对应总表](../模型与标签对应总表.md) 的 53 行关系：63 个模型或工具代号、51 类标签，其中 6 类尚无确认 producer。63 个代号包含泛称、组合工具和不可调用的旧候选，不表示 63 个已部署模型。

总表中的逗号表示共同参与，斜线表示替代选项。例如 `{a,b}` 需要同时选择 a 和 b，`{a / b}` 选择任一个即可。只有整条路径的模型条件满足，才计入其输出标签；单条曲线只表示参与关系。同一标签优先归入“有依据路径”，只有全部满足路径都含 H 时才归入“仅候选路径”，避免重复计数。

`m_asr`、`m_diarizer`、`m_event` 是总表中的角色泛称，具体实现另行指定；前端按原表代号计算，不擅自把某个具体模型视作所有泛称的替代者。选择这些节点表示满足组合的角色条件。强制对齐所需文字/语言、模型权重、任务头、后处理、适配和质量验证仍以详情与原始研究文档为准。

标签按稳定 ID 去重；`[frame]`、`[median]`、`[target]` 等限定保留在路径详情和导出中。路径满足不证明全部粒度已支持，不证明模型可即时运行或已通过准确率验证。页面不执行模型推理。

## 更新数据

修改总表或当前 schema 后运行：

```bash
python3 docs/research/speech-evidence-space-20261020/visualization/build_data.py
```

脚本读取原研究总表、`tag_schema.md`、`schema_comparison.json`，以及新版能力表 MD/JSON，生成 `data.js`。新版 16 条关系从 Markdown 第 5 节的 M01–M08 / X01–X08 解析，同时输出 [sure_cross_checks.json](sure_cross_checks.json)；构建时检查公共字段引用、唯一 ID 和 `planned` 状态，`check_result` 保持 `null`。原研究关系保存在 `CROSS_CHECKS`。页面加载本地脚本，没有 `fetch`，支持直接打开本地文件。

旧新字段的语义映射由人工依据文档核对，保存在 `schema_comparison.json`；新增或调整类型时需同步维护该文件和对比报告。`baseline-tag-schema.md` 是指定 2026-10-09 共享文档的逐字节快照；共享源文件没有被修改。旧父字段与新语义类型的粒度不同，不能直接用数量相减推算新增标签。

实现文件：`index.html` 布局、`styles.css` / `app.js` 原研究视图、`sure.css` / `sure.js` 新版公共字段视图、`build_data.py` 数据构建、`data.js` 数据快照。
